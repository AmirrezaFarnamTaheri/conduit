# Operations

## Storage and retention

Blob storage is content-addressed and deduplicated. Session logs are append-only. Back up the runtime directory only if its contents are approved for backup; it may contain sensitive output. `gc` and retention policy are planned operational surfaces, so do not assume an unbounded store is safe for long-running deployments.

## Diagnostics

When behavior is unexpected, collect the command, profile, exit code, presented output, and handle—not secrets or the full raw blob by default. Confirm the workspace and `CONDUIT_HOME` values first. Re-run with the raw handle only when necessary.

## Recovery

A missing or expired handle requires rerunning the command. A stale edit must be regenerated from a fresh atlas hit. A held edit lock should be investigated before removal; deleting it while another process is active can allow concurrent writes.

## Release checklist

- Rust format, workspace tests, clippy, and cross-platform matrix are green.
- Python benchmark and release gate are green.
- `cargo-deny` reports no unapproved advisories, licenses, or sources.
- Threat-model changes are reviewed.
- Artifacts, checksums, SBOM, and provenance are generated by the release pipeline.
- No credentials, raw runtime state, or unreviewed generated files are included.

## Incident principles

Stop at the smallest safe boundary, preserve append-only evidence, avoid destructive cleanup, and prefer a reproducible rerun over manual state editing.
