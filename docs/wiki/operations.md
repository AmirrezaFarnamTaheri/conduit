# Operations

## Storage and retention

Blob storage is content-addressed and deduplicated. Session logs are append-only. Back up the runtime directory only if its contents are approved for backup; it may contain sensitive output. `gc` and retention policy are planned operational surfaces, so do not assume an unbounded store is safe for long-running deployments.

## Diagnostics

Run `conduit doctor` to verify stored blob contents and identify unexpected shard entries. `doctor` reads object contents, so restrict access to authorized operators. It is read-only and neither deletes staging files nor races-freezes concurrently published objects. Run `conduit stats SESSION` to validate session accounting without building an in-memory list of all events. `repair-session SESSION` completes a valid unterminated event or quarantines a malformed tail before truncation; retain and protect the reported `.torn-*.bak` file according to your incident policy.

When behavior is unexpected, collect the command, profile, exit code, presented output, and handle—not secrets or the full raw blob by default. Confirm the workspace and `CONDUIT_HOME` values first. Re-run with the raw handle only when necessary.

## Recovery

A missing or expired handle requires rerunning the command. A stale edit must be regenerated from a fresh atlas hit. The edit lock is held by the OS for the process lifetime and released automatically on process exit; do not delete the file while edits are active because that could create separate lock inodes. For multi-file batches, an interrupted commit may leave a partially applied set: `batch-edit --check` does not constitute crash recovery. Preserve original files/backups and reconcile hashes before retrying. A torn session tail requires explicit `repair-session` after evidence preservation.

## Release checklist

- Rust format, workspace tests, clippy, and cross-platform matrix are green.
- Python benchmark and release gate are green.
- `cargo-deny` reports no unapproved advisories, licenses, or sources.
- Threat-model changes are reviewed.
- Artifacts, checksums, SBOM, and provenance are generated by the release pipeline.
- No credentials, raw runtime state, or unreviewed generated files are included.

## Incident principles

Stop at the smallest safe boundary, preserve append-only evidence, avoid destructive cleanup, and prefer a reproducible rerun over manual state editing.
